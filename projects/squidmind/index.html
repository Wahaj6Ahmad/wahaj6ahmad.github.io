SquidMind

A tentacled memory game robot that teaches turn-taking through lights, motion, and voice

SquidMind, ready to judge your memory skills.

I built SquidMind in the Human-Robot Communication course at the University of Twente (Challenges 2 and 3, Oct 2022). Challenge 2 pushed us into pure non-verbal interaction. So we designed a simple color-pattern memory game where the robot communicates through LED expressions and physical input through its “tentacles”.

In the final iteration (Challenge 3), we were allowed to add semantic communication. That let us upgrade the same robot into something more social: a game built around clear turn-taking and guidance, so the interaction doesn’t rely on guesswork.

Demo

If you’ve seen my Roboception project, then you can see my overthinking of the blinking animations has come to fruition here. SquidMind has opinions, and it expresses them with LEDs.

What the robot does

SquidMind runs a color-pattern memory game with a “my turn / your turn” rhythm. The robot shows a sequence of colors, waits for the user to reproduce it through the tentacles, then responds with immediate feedback. In the final version, voice is used to make the structure and expectations explicit, so the user doesn’t have to infer the rules from lights alone.

Technical details

Interaction logic

The core loop is intentionally simple: show a pattern → wait for input → confirm correctness → increase difficulty. The biggest design shift from Challenge 2 to Challenge 3 was clarity: we kept the same game, but used voice to support turn-taking and reduce ambiguity in “what do I do now?”

Gameplay state: SquidMind displaying the color sequence.
Correct input reaction: this is SquidMind being proud of you.
Wrong input reaction: disappointment, but make it educational.

Tech used

  • Embedded prototyping: tentacle inputs (sensors/buttons) + LED feedback
  • LED “face” expressions for state + feedback (gameplay, correct, wrong)
  • Servo-based movement used as an extra layer of communication (non-verbal cues)
  • Turn-taking interaction design, upgraded with voice in the final iteration
  • Rapid physical prototyping (cardboard body + iterative rebuilds)
Evaluations + learnings

Evaluation

We tested SquidMind with participants to see whether the cues were understandable, whether turn-taking felt clear, and where people got stuck (or formed the wrong mental model).

Evaluation moment: this is where the real bugs show up.
What worked well
  • LED expressions made the robot’s state readable during gameplay.
  • The correct/wrong feedback was immediate and easy to interpret.
  • Voice (final iteration) helped remove ambiguity in “what’s expected from me right now?”
What I’d improve next
  • Make the “start / activation” affordance impossible to miss (people will default to button-hunting).
  • Tighten the tutorial: teach by doing, then keep explanations short during play.
  • Harden the system for real-world use: handle interruptions, retries, and the weird stuff humans do mid-game.

Why this matters for my robotics path

SquidMind is the kind of project that sits right in the middle of what I want to do as a roboticist: building systems where hardware, behavior, and human interpretation all have to line up. The LEDs and tentacles were the easy part. The hard part was designing cues that people understand consistently, then validating that with real users and iterating from what broke.

  • HRI thinking: designing interaction logic around turn-taking and expectations
  • Embodied feedback: using light + motion as communication channels, not decoration
  • Iteration through testing: finding the points where users form the wrong mental model, then fixing those
